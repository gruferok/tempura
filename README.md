# Tempura · Rhythm Lab

Рабочий **нативный Python/Pygame-прототип**: PCM-аудиоядро с часами по DAC, двухпроходная калибровка, Live-разметка, плейтест и **AI Studio** — обучение CNN + BiGRU на ваших картах и offline-генерация Tap/Hold для 1–8 дорожек. Внешние веса и датасеты не скачиваются.

## Запуск

Нужен **Python 3.11+**. Для игры — локальный дисплей и выходное аудиоустройство; для обучения и генерации через CLI они **не требуются**.

```bash
python3 -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1

# CPU-сборка Torch без CUDA-зависимостей:
python -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements-dev.txt
python main.py --diagnose
python main.py
```

Для NVIDIA/Apple вместо CPU-строки сначала установите совместимую с вашей платформой сборку PyTorch. `requirements-ml.txt` допускает Torch `>=2.6,<3.0`, не заменяя уже подходящую CPU/CUDA/MPS-сборку. Выбор устройства в коде: **CUDA → MPS → CPU**; можно принудительно указать `--ml-device cpu`.

Зависимости разделены: `requirements.txt` — игра без Torch; `requirements-ml.txt` — игра + AI; `requirements-dev.txt` — AI + pytest. Базовое меню и headless-рендер AI Studio работают и без Torch; обучение/генерация выдадут понятную инструкцию установки.

Linux дополнительно требует нативный **PortAudio**. Например, на Debian/Ubuntu:

```bash
sudo apt-get install libportaudio2 libsndfile1
```

На Windows/macOS sounddevice обычно поставляет нативную библиотеку через wheel. Это не устанавливает драйвер вашего аудиоустройства.

В текущем sandbox используется локально собранный PortAudio в `.venv/lib`: для него предусмотрен launcher:

```bash
chmod +x run.sh
./run.sh --diagnose
./run.sh
./run.sh --test -q
```

В Windows: `.venv\Scripts\python.exe main.py`. В качестве модуля устанавливается **pygame-ce**, импортируется он как `pygame`. Не устанавливайте одновременно обычный `pygame` в ту же venv.

Другие параметры:

```bash
python main.py --audio /path/to/song.flac
python main.py --chart data/charts/test_track_4K.json
# Короткий демонстрационный фрагмент без предварительной записи:
python main.py --chart data/charts/schema-example.json
python main.py --device 3
python main.py --diagnose --report environment.json
```

`--device` принимает индекс из диагностики или имя устройства. Отсутствие устройства не заменяется фальшивым wall-clock playback: меню сообщает ошибку, а аппаратные режимы требуют реального выхода.

## 1. Калибровка

В меню нажмите **1**. Сделайте два прохода, **минимум по 16 отдельных нажатий SPACE**:

1. **По звуку:** слышен метроном 120 BPM; визуальной beat-подсказки нет.
2. **По изображению:** метроном выключен; нажимайте при пересечении индикатором центральной линии.

Повторные нажатия на той же доле и слишком далёкие нажатия отклоняются. Медиана и MAD-фильтр снижают влияние выбросов. **R** перезапускает проход, **Esc** отменяет без сохранения; сохранение в `config.json` подтверждается отдельно.

Обозначения и знаки:

```text
A = median(audio tap time - metronome beat time)
V = median(visual tap time - visual crossing time)
audio_offset_ms  = A
visual_offset_ms = V - A

judgment_time = raw_song_time - audio_offset_ms / 1000
render_time   = raw_song_time + visual_offset_ms / 1000
```

Таким образом положительный audio offset компенсирует поздний ввод; положительный visual offset сдвигает ноты визуально раньше. Audio offset применяется к Live-вводу при записи и к вводу в плейтесте, **не повторно к уже сохранённым нотам**. Visual offset не меняет аудио, judgment или времена карты.

Это **эффективная калибровка игрока**, включающая response bias, а не чистое измерение hardware latency. Две независимые аппаратные задержки невозможно определить одной серией нажатий. После смены наушников, backend, sample rate, монитора или устройства повторите калибровку. При underrun или потере фокуса текущая калибровка не принимается.

## 2. Live-разметка

- **T** в меню — синтетический трек 48 s, 120 BPM, клики и мелодия; первые 2 s — вступление.
- **O** — встроенный файловый браузер для WAV/FLAC/OGG/MP3/AIFF и поддерживаемых libsndfile форматов. Enter открывает выбранное; Backspace поднимается к родителю. Можно положить свою музыку в `data/audio/` (она исключена из Git).
- **2** — начать Live-разметку, затем выбрать раскладку:
  - **1K:** Space;
  - **2K:** F J;
  - **4K:** D F J K;
  - **C / «Своя»**: от 1 до 8 уникальных клавиш слева направо, затем Enter.
- События KEYDOWN/KEYUP записываются по аудиочасам. Повтор KEYDOWN не создаёт ноты. До старта presentation и во время transport transition ввод не записывается.
- Удержание **строго дольше 150 ms** становится Hold; остальное — Tap. Порог можно изменить в конфигурации.
- **P** — пауза/продолжение; **R** — заново с подтверждением; **Backspace** — удалить последнюю законченную ноту; **S** — сохранить и выйти. **Esc** предлагает сохранить запись и выйти, отмена оставляет запись на паузе.
- **Left / F2 — Rewind на 5 секунд.** Если Left назначена дорожке собственной раскладки, она продолжает записывать ноты, а откат доступен на F2. Backspace остаётся удалением одной последней ноты.
- При естественном окончании трека карта сохраняется автоматически. Активные удержания закрываются при паузе/сохранении/конце трека. Потеря фокуса ставит запись на паузу. **W** скрывает/показывает радар атаки с RMS-волной на 20 ms bins и lookahead 1.8 s; время радара учитывает `visual_offset_ms`. **V** переключает vertical/horizontal; **F3/F4** замедляют/ускоряют прокрутку, сохраняя `scroll_seconds` в `config.json`.

### Rewind: переписать фрагмент, не начиная песню заново

- Откат ограничен началом трека. Нажатия несколько раз подряд суммируют по 5 s даже до callback/DAC-предъявления предыдущего seek. Пауза сохраняется; из паузы продолжите клавишей **P**.
- Ноты со стартом на/после новой границы удаляются. Hold, начавшийся раньше и пересекающий границу, обрезается; если оставшаяся часть не превышает hold threshold (150 ms по умолчанию), она становится Tap. То же правило действует для ещё зажатых клавиш.
- Новая аудиопозиция выравнивается по sample; граница удаления в JSON-временах равна `raw_rewind_target - audio_offset_ms / 1000`, с ограничением допустимым диапазоном карты. Смещение не вычитается повторно из оставшихся нот.
- Активные клавиши сбрасываются: отпустите их и нажмите заново для перезаписи. Пока seek не достиг DAC, ввод не записывается; события с timestamp из старого transport epoch отбрасываются, в том числе KEYUP. На экране показаны `ОЖИДАНИЕ DAC` и счётчик Rewind. Предел точности SDL timestamp/polling остаётся тем же, что описан ниже.
- Изменяется запись в памяти; на диск она попадает только при обычном сохранении/конце трека. Backspace **не** возвращает удалённый откатом фрагмент. В metadata сохраняются `rewind_count` и `rewind_seconds`.

Файл: **`data/charts/<track_name>_<lanes>K.json`**. Повторное сохранение той же песни и количества дорожек атомарно заменяет файл. Чтобы хранить несколько дублей, скопируйте/переименуйте предыдущую JSON-карту до новой записи. Пользовательские карты исключены из Git.

Петля режимов нацелена на **300 FPS** (настраивается, минимум 240), с выключенным vsync. Это целевая частота, не гарантия на любом компьютере. Используется SDL timestamp события, если pygame его предоставляет; иначе — время извлечения события из очереди. Фактический FPS показан на экране.

### Smart Beat-Snap: необязательное выравнивание небольших ошибок

После сохранения Live-записи (S, подтверждение Esc или конец трека) аудиопоток **закрывается**, а исходная карта уже лежит на диске. Открывается экран Smart Beat-Snap; **Esc** сразу возвращает в меню без анализа и изменений. Для ранее сохранённой карты нажмите **B / Beat-Snap сохранённой карты** в главном меню и выберите JSON с тем же исходным аудио.

1. Выберите окно **15 / 20 / 25 ms** кнопками или клавишами **1/2/3**; по умолчанию 25 ms.
2. **B — Найти атаки / Beat-Snap**. Librosa в фоновом worker находит спектральные onset-пики, затем уточняет начало атаки по энергии с шагом около 1 ms. Tempo/beat tracking — только подсказка: сетка не продолжается через тишину, новые доли и ноты не выдумываются. На плавных/шумовых атаках консервативный детектор может оставить ноты без изменений.
3. Сдвигаются только начала нот, у которых реальная найденная атака внутри выбранного окна. Ноты далеко от сетки, в том числе намеренные синкопы, остаются. Дорожки, число/типы нот, точные аккорды и **длительности Hold** сохраняются: Hold сдвигается целиком, его хвост не привязывается отдельно. При конфликте в одной дорожке или выходе Hold за конец трека сдвиг всего затронутого аккорда отменяется, ноты не сливаются и не удаляются.
4. Экран показывает число/максимум сдвигов, конфликты и первые изменения до/после. Изменение окна пересчитывает preview без повторного анализа аудио. **P** — плейтест несохранённой копии. **Enter / Сохранить отдельную копию** — явное принятие результата; **Esc** отбрасывает preview.
5. Результат: **`<исходный_stem>_snap.json`**, затем `_snap_2.json` и т. д. Ни исходная карта, ни предыдущая snap-копия не заменяются. Если сдвигов нет, пустая копия не создаётся. Записываются алгоритм/окно/статистика, имя и SHA-256 исходного JSON.

Таймлайн уже скорректирован при Live-записи: Beat-Snap не читает конфигурацию калибровки и не вычитает audio/visual offset повторно. Анализ не использует модель, CUDA или PyTorch и не работает в audio callback. Отмена проверяется между тяжёлыми операциями Librosa; первый запуск может занимать заметно больше времени из-за импорта/JIT.

Snap-копия помечается `auto_quantized: true`, `human_reviewed: false` и по умолчанию исключена из Train. **T** на экране Beat-Snap переключает `include_in_training`; решение сохраняется в JSON при Enter, а включение — явный opt-in именно для этой автоматической копии. Кнопка сама не заявляет, что каждая нота музыкально проверена; при сомнении оставьте копию выключенной.

Это консервативный onset-snap, а не гарантированно точная партитура/разделение инструментов; на сложных треках оценивайте результат на слух. Физическую задержку аудиовыхода он не измеряет и калибровку не заменяет.

## 3. Плейтест

**3** в меню → выберите сохранённый JSON. Исходное аудио загружается из карты. Если файл перемещён, выберите его заново; SHA-256 проверяет идентичность. Синтетический трек воспроизводится по сохранённым параметрам генератора.

| Оценка | Окно |
|---|---|
| Perfect | ±25 ms включительно |
| Great | ±50 ms включительно |
| Good | ±90 ms включительно |
| Miss | пропуск или выход за окно |

Показаны signed delta в ms (**early < 0**, **late > 0**), combo, accuracy и счёт. **V** переключает вертикальные/горизонтальные дорожки; **F3/F4** меняют и сохраняют скорость прокрутки. Judgment учитывает дорожку. Для Hold нужно и начать, и **отпустить** ноту вовремя; итог — худшая из двух оценок. Раннее отпускание и удержание более чем на 90 ms после хвоста дают Miss. Пустые нажатия учитываются отдельно и не получают очков. **P** — пауза, **R** начинает/завершает Punch-In-сегмент, **Esc** — выйти. Во время записи Punch-In исходные нажатия не оцениваются: на завершении сегмента ноты с onset внутри интервала заменяются, ноты снаружи сохраняются, пересекающий границу Hold обрезается. Исходный JSON не перезаписывается: после выхода Enter создаёт отдельную `_overdub`-копию, **T** включает её в обучение, Esc отбрасывает запись. Пауза закрывает активные Hold по текущему времени и может дать Miss: это плейтест, не соревновательный pause exploit.

После игры показывается гистограмма попаданий −90…+90 ms, среднее signed error, SD и **Unstable Rate = SD × 10**. При ≥16 успешных попаданиях и `|mean| ≥ 4 ms` клавиша **O** предлагает добавить среднюю ошибку к `audio_offset_ms` и сохранить `config.json`; отклонение поздних нажатий положительное, поэтому offset увеличивается, чтобы компенсировать его. Автоподстройка не применяется сама.

## 4. AI Studio · обучение и автогенерация

В главном меню **4 / A** открывает AI Studio. Экран показывает модель (нет / процедурный cold start / дообучена на ваших картах), число карт-кандидатов и устройство. Повреждённое или отсутствующее исходное аудио проверяется уже при загрузке датасета; причины пропуска попадают в метаданные модели.

1. Запишите свои треки в Live-режиме; положите JSON в `data/charts/` и не перемещайте исходное аудио. У Live-карт `include_in_training: true` по умолчанию. **D / Dataset** открывает список карт; ↑/↓ выбирает, **T** включает/исключает конкретную карту атомарно. AI-карты всё равно требуют `human_reviewed: true`. Можно начать с 1–3 карт, но надёжность личного стиля оценивайте на **новых**, не обучающих треках.
2. **T / Train / Fine-tune**: новая модель сначала проходит процедурный bootstrap, затем обучается на ваших картах. Существующая модель продолжает fine-tune без повторного bootstrap. По умолчанию: 12 синтетических аудиопримеров по 6 s, 3 bootstrap-эпохи, затем 8 эпох на всех пригодных пользовательских картах. Если карт ещё нет, сохраняется честно обозначенная модель `bootstrap_only`.
3. **O** — выбрать собственный трек; **Y** — тестовый. **1/2/4** — раскладка; **C** — выбор собственной, до 8 клавиш. Фактические клавиши видны под кнопками.
4. Ползунок или **Left/Right** меняет плотность: `threshold = 0.8 - 0.6 × sensitivity`; выше плотность — ниже порог. **G / Generate AI Chart** запускает нейросетевой инференс и сохраняет **`data/charts/<track>_ai_<lanes>K.json`**. Существующий AI-дубль той же раскладки заменяется, Live-карта не затрагивается.
5. **[ / ]** переключает профили `personal_default`, `style_a`, `style_b`; веса и sidecar metadata хранятся раздельно как `data/models/rhythm_model_<profile>.pt`. **Enter** — сразу плейтест последней сгенерированной карты с тем самым аудио. Её также можно открыть через пункт 3 основного меню.

Обучение/генерация идут в одном фоновом worker, с прогрессом эпох/батчей, loss и временем; Pygame остаётся в основном потоке. Параллельные задания и плейтест во время обучения не запускаются. Кнопка отмены оставляет экран открытым; **Esc** отменяет задание и возвращает в меню после безопасной границы. Отмена проверяется между тяжёлыми операциями/батчами, не прерывает FFT или GPU-kernel посередине. Аудиопоток во время ML-операций не открывается.

### CLI без дисплея и аудиоустройства

```bash
# Новая модель: bootstrap + все Live-карты; существующая: fine-tune
python main.py --train --ml-device auto

# Повторное дообучение, параметры можно менять
python main.py --train --epochs 12 --batch-size 4 --learning-rate 0.001

# Аудиофайл или встроенный 48-секундный трек
python main.py --generate /path/song.flac --lanes 2 --threshold 0.55
python main.py --generate synthetic --lanes 4 --sensitivity 0.6
python main.py --generate /path/song.wav --lanes 3 --keys d f j

# Обучить, затем сгенерировать одним запуском
python main.py --train --generate /path/song.wav --lanes 4

# Opt-in holdout по целым трекам, когда есть >=3 разных аудио
python main.py --train --validation-fraction 0.2

# Заново только bootstrap. Внимание: заменит личную модель после успеха!
python main.py --train --reset-model --epochs 0 --ml-device cpu
```

Дополнительно: `--model <path.pt>`, `--charts-dir <dir>`, `--output <chart.json>`, `--no-cache`, `--window-seconds`, `--bootstrap-epochs`, `--bootstrap-samples`, `--seed`. `--threshold` и `--sensitivity` взаимоисключающие. `--ml-device` — **не** аудиопараметр `--device`. Прогресс CLI выводится JSON-строками в **stderr**, итог — JSON в **stdout**. Если модель уже есть, но пригодных Live-карт нет, повторный Train не портит её пустым обучением: добавьте карты либо явно используйте `--reset-model`.

### Что именно учится

- **Признаки:** анализ 16 kHz, FFT 512 с центровкой, hop **160 samples = ровно 10 ms**. На frame `k` время `k/100` s; форма `[ceil(duration×100), 130]`: 64 Log-Mel + 64 первых разностей + Onset Strength + спектральный Flux. Поколоночная z-нормализация **всего трека**, одинаковая для обучения и инференса; тишина даёт конечные нули. Кэш `.cache/ml/features/` учитывает аудио-id, частоту и версию/параметры признаков; pickle не используется.
- **Метки:** `[T, 8]`, onset — максимум Gaussian с **σ=1.5 frame = 15 ms** вокруг дробного момента старта; Hold — 1 внутри `[start, end)`. Уже исправленный в Live `audio_offset` **не применяется повторно**. Окна по 10 s, stride 5 s, маски времени и активных дорожек; Gaussian строится до нарезки.
- **RhythmCRNN:** temporal Conv1d по Mel/delta-каналам (48 channels), эмбеддинг числа дорожек (12), **BiGRU 48×2**, две головы onset/hold по 8 logits. Это маленькая модель примерно на 72 тыс. параметров, не большой предобученный музыкальный энкодер. Bidirectional-контекст делает генерацию offline.
- **Обучение:** AdamW, masked BCEWithLogits (положительный вес по soft positive mass, cap 30), вес hold-loss 0.5, gradient clipping. Fine-tune существующей модели использует половину указанного LR; AdamW создаётся заново для каждой фазы/запуска, состояние optimizer не сохраняется. Loss/history, параметры, hashes карт и режим обучения записываются в метаданные.
- **Валидация:** по умолчанию используются все пригодные Live-карты. При `--validation-fraction 0.2` и >=3 разных аудио holdout разделяется **по id целого трека**, не по окнам/раскладкам, без такой утечки train/validation. Малый training loss сам по себе не измеряет качество генерации.
- **Декодирование:** инференс окнами 12 s с overlap 2 s и плавным смешиванием. Локальные максимумы onset, минимум **70 ms на одной дорожке**, Hold по hold-probability с объединением провалов 10–20 ms. Hold должен быть **>150 ms**, обрезается по следующему onset той же дорожки/EOF. Микроскопический float32-шум смешивания не создаёт ложные пики. Смещения проигрывателя и визуала в AI-времена не запекаются.

**Защита данных:** demo-карты, пустые карты, записи с underruns, а также AI-карты и Beat-Snap-копии без **boolean** `metadata.human_reviewed=true` исключаются из обучения. Не включайте этот флаг автоматически: это ручное подтверждение после настоящей проверки/правки карты. Иначе модель будет учиться автоматическим ошибкам/дублям. Отсутствующее/несовпадающее по SHA-256 аудио пропускается с причиной, не заменяется другим треком.

Чекпоинт **`data/models/rhythm_model.pt`** и небольшой JSON-sidecar сохраняются локально. В `.pt` только `state_dict` и простые метаданные; загрузка — **`torch.load(weights_only=True)`**, с проверкой версии признаков/архитектуры. Сохранение весов атомарное; ошибка/отмена до публикации не уничтожает старую модель. Веса, кэш и пользовательские/AI-карты исключены из Git; обученную модель можно переносить между CPU/CUDA/MPS при наличии совместимого Torch. Произвольные старые pickle-чекпоинты не поддерживаются.

**Ограничения:** cold start учится на синтезированных ритмах, паузах, аккордах и удержаниях — это не доказательство понимания реальной музыки. Модель после 1–3 карт может переобучиться; освоение новых жанров, рисунков и числа дорожек нужно проверять. Иногда результат пустой или слишком аккордовый: меняйте плотность, добавляйте разнообразные Live-примеры и сравнивайте на новых треках. Сетка 10 ms не гарантирует физическую точность 10 ms. Никакая эвристическая «запасная карта» не выдаётся за предсказание сети.

## Аудиоядро

- Файл целиком декодируется в stereo `numpy.float32`; resampling выполняется **до** открытия потока.
- Единственный sounddevice `OutputStream`: PCM песни + синтезированный метроном и hitsounds смешиваются в callback. Pygame mixer не инициализируется.
- Click samples синтезируются заранее; bounded command/hit queues, фиксированный voice pool, in-place mixing и clipping. В callback нет файлового I/O, ML, sleep или блокирующих mutex.
- Hitsound попадает в **первый ещё не отрендеренный буфер**, а не в уже отправленные устройству samples. Нулевая физическая задержка не обещается.
- Часы:

  ```text
  song_time = anchor_song_time + (stream.time - anchor_dac_time)
  ```

  `anchor_dac_time` берётся из `time.outputBufferDacTime`, а `stream.time` читается **только вне callback**. Output latency второй раз не вычитается.
- Pause/seek/stop вступают в силу на DAC-границе следующего буфера. История сегментов сохраняет старый участок, пока он ещё в аудиоочереди; после pause позиция заморожена, хотя stream.time продолжает идти. Старт/конец также отслеживаются по presentation time, а не по записи последнего frame в callback.
- Underruns считаются и видны на экране; новый буфер re-anchor'ит известную позицию, но потерянные/вставленные драйвером frames невозможно восстановить с гарантией. Не используйте запись с underruns для точной оценки синхронизации. Если backend не даёт пригодный DAC timestamp, приложение сообщает ошибку, а не подменяет часы таймером ОС.
- **Soft real-time:** Python/GIL и драйвер могут дать jitter. Есть небольшие Python-аллокации; это не «allocation-free native DSP». Подбирайте минимальный **устойчивый** буфер на целевом устройстве.

Основные настройки находятся в `config.json`: `sample_rate`, `output_device`, `latency` (`low`, `high` или секунды), `blocksize` (`0` — выбор backend), `volume`, `fps`, `scroll_seconds`, offsets. Неправильная конфигурация выдаёт ошибку, а не молча сбрасывается.

## Проверки

```bash
python -m pytest -q
python main.py --headless-smoke
# Необязательный снимок меню без окна:
python main.py --headless-smoke --screenshot .cache/menu.png
```

В этом sandbox: **Debian 12, Python 3.11.2, 2 CPU; CUDA=false, MPS=false; дисплея и аудиоустройств нет**. CPU-индекс `download.pytorch.org` недоступен (TLS-соединение закрывается сетевым окружением). Поэтому установлен официальный **PyPI Torch 2.6.0+cu124**, включая его CUDA-библиотеки, но **все обучения/инференсы выполнялись на CPU**. Это не CPU-wheel и не тест GPU; на локальной CPU-машине предпочтительна команда CPU-индекса выше. `requirements-lock.txt` фиксирует именно эту sandbox-установку; для другого ПК используйте подходящую сборку + `requirements-ml.txt`.

PortAudio собран локально с OSS backend без устройств — это только проверка импорта, не рабочий low-latency output на сервере. Точная диагностика, включая сборку Torch, в [`docs/environment-check.json`](docs/environment-check.json).

Последняя проверка после радара/ориентаций и dataset controls (предыдущие функции сохранены):

- `./run.sh --test -q` — **200 passed за 21.39 s**, включая 4 новых Punch-In/аналитики проверки. 22 предупреждения только о недоступных системных шрифтах (используется встроенный Pygame font).
- `--headless-smoke` — отрисованы все **7 экранов**, включая AI Studio и Beat-Snap, аудиопоток не открывался.
- `python -m compileall -q main.py src tests` — успешно; `python -m pip check` — конфликтов нет. UTF-8/newline/whitespace-проверка 37 исходных/документальных файлов — без ошибок.
- Отдельный Beat-Snap smoke: 48 s синтетического трека, 92 ноты с искусственным опозданием на 18 ms → 92 найденные атаки / 92 сдвига, максимальный сдвиг 18.86 ms, 0 конфликтов; анализ + preview 4.40 s при уже готовом JIT-кэше. Это технический fixture, не проверка музыки/физической задержки и не гарантия времени на другом ПК.

Ранее выполненные ML-замеры (2026-11-15; не повторный бенчмарк после Rewind/Beat-Snap):

- Реальный запуск `--train --ml-device cpu` без пользовательских карт: 12 процедурных примеров, 3 эпохи, **5.27 s внутри pipeline / 6.97 s всей команды**, train-eval loss **1.7694 → 1.1233**, чекпоинт **293,981 bytes**. Это один замер в этой среде, не обещание скорости на другом ПК.
- Этот **bootstrap_only**-чекпоинт сгенерировал совместимые с `Chart`/`Judge` JSON для 48-секундного тестового трека: 1K — 92 ноты, 2K — 184, 4K — 368, 8K — 552. 4K pipeline занял 0.95 s; остальные с кэшированными признаками — 0.17–0.20 s. Число нот подтверждает выполнение, **не музыкальное качество**; у cold start возможны избыточные аккорды. Локальные веса и эти пробные карты не добавлены в Git.

Автотесты вызывают **настоящий AudioEngine callback через моделируемый stream** и проверяют timing/transport, JSON, калибровку и Tap/Hold. Beat-Snap-тесты проверяют атаки при 8/24/48 kHz (включая противофазное stereo), нерегулярный ритм, тишину, окна/границы, Hold/аккорды/каскадные конфликты, случайные 8K-карты, неизменность оригинала и уникальные копии, исключение из Train, opt-in/отмену/ошибки/плейтест/сохранение и настоящий фоновый worker. Экран работает и при скрытом Torch. ML-тесты проверяют частоту/центрирование/кэш признаков, Gaussian-метки, маски и градиенты, все 1–8K, уменьшение loss на тестовой карте, продолжение обучения, отмену без потери старых весов, безопасную сериализацию, пики/удержания/границы, настоящий инференс в JSON, UI Train → Generate → Playtest, CLI без hardware и базовый рендер даже при скрытом Torch.

Они **не доказывают** физическую задержку DAC/монитора, >=240 FPS на настоящем дисплее, качество человеческой калибровки, перенос личного стиля на новые треки или работу GPU-kernels. Человеческих Live-карт в sandbox пока нет; подгонка loss проверена на отдельной синтетической тестовой карте, не на разметках пользователя. Сам звук, ввод и музыкальность AI нужно проверить локально на вашем оборудовании.
